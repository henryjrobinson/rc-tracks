# Ralph Progress Log — rc-tracks Trip Planner

## Codebase Patterns
- All filter state lives in `app/track-browser.tsx`; child components are presentational.
- The view-toggle pattern is in track-browser.tsx — extend it for new views.
- `app/map-view.tsx` is dynamically imported with `ssr: false` to avoid Leaflet/window crashes.
- Geo helpers (geocoding, haversine, geolocation, network calls) belong in `lib/geo.ts`.
- localStorage caches use a versioned key (e.g. `rc-tracks:geocode-cache:v1`) and JSON.parse with try/catch.
- The Track type is in `site/lib/tracks.ts`. The data file is `site/data/tracks.geocoded.json`.
- All styles in `site/app/globals.css`. Mobile-first; `@media (min-width: 720px)` for desktop.
- Touch targets ≥44px (use `min-height: 44px` for inputs/buttons).
- Map markers use `L.icon({ iconUrl: 'https://unpkg.com/leaflet@1.9.4/dist/images/marker-icon.png', ... })` to avoid bundler issues.
- Build verifies with `cd site && npx tsc --noEmit && npm run build`.

## 2026-05-08T00:00:00Z - TRIP-2
- Added `Route` type and async `getRoute(start, end, signal?)` to lib/geo.ts. Calls OSRM public demo (`router.project-osrm.org`) with `overview=full&geometries=geojson&steps=false`. Maps GeoJSON `[lon, lat]` pairs to `{ lat, lon }`, converts meters→miles and seconds→minutes. Returns null when no route is found; throws on HTTP errors so callers can show a friendly message.
- Files modified: site/lib/geo.ts.
- **Learnings:**
  - GeoJSON coordinates are `[lon, lat]` — remember to swap when constructing `LatLon`. The existing codebase consistently uses `{ lat, lon }`, so any new geo helper should normalize at the boundary.
  - OSRM's public demo has no auth and rate limits per IP. It's fine for a hobby site but TRIP-4 should AbortController-cancel in-flight requests on resubmit (already in story acceptance criteria).
  - Don't trust `routes[0].geometry?.coordinates` to be defined — typed as optional in the response type. Guard before mapping.
  - Conversion constant: 1 mile = 1609.344 m exactly; using a literal avoids importing/exporting another constant.

## 2026-05-08T00:00:00Z - TRIP-3
- Added `pointToPolylineMiles(p, polyline)` plus a private `closestPointOnSegment` helper to lib/geo.ts.
- Empty polyline → Infinity; single-point polyline → haversine to that point; else iterate consecutive segments.
- Per-segment projection uses an equirectangular approximation: scale longitudes by cos(midLat) so the segment becomes a flat 2D line, project p onto it, clamp t∈[0,1], then haversine the closest lat/lon back.
- Files modified: site/lib/geo.ts.
- **Learnings:**
  - For the corridor test (TRIP-4+), each candidate track only needs one representative LatLon, so callers can pass `[track.location]`-style polylines OR the full OSRM route — the helper is symmetric in roles. The PRD wording suggests we'll pass `pointToPolylineMiles(trackLatLon, route.polyline)`.
  - Equirectangular is plenty accurate for trip-corridor distances (<100 mi). No need for spherical law of cosines per segment — the haversine on the closest projected point is the great-circle measurement that matters.
  - We scale by `cos(midLat)` not `cos(meanLat)` — works because OSRM polylines are dense enough that each segment spans tiny degrees. Avoid converting to meters explicitly; the unit cancels in the t-formula.
  - Keep the helper pure (no fetch, no globals) so TRIP-4 can call it inside a `useMemo`.
